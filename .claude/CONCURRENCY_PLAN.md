## Shared rules for every builder (read once)
- Stale-edit hash = md5 of the form's own columns from a PLAIN read of the base table (never a JOIN row: the edit-booking
  load at `admin/edit-booking.php:48-57` aliases `ir.id as individual_room_id`). The same column list and the same helper are
  used at render and at save.
- On save: inside the transaction, `SELECT <cols> ... WHERE id = ? FOR UPDATE`, recompute, compare with `hash_equals`. If they
  differ, roll back with nothing written. A missing or empty posted hash is also refused ("This page was opened before a
  change to how saving works. Reload it and try again.").
- A form re-shown after an error with the person's typed values carries the POSTED hash forward, never a fresh one. Every
  opener and reopen path is listed in its task.
- A same-page action that writes a hashed column (a toggle, an image upload) returns the new hash in its JSON reply, and the
  page JS stores it. Otherwise the next Save is falsely refused.
- Message pattern: "<Thing> was changed by someone else since you opened it, so nothing was saved. Reload the page to see the
  new details, then make your change again." Name a person and a time only where a real source exists: `booking_audit_log`
  (bookings), `setting_change` rows (settings), `import_jobs.created_by/created_at`, `stock_counts.counted_by/created_at`.
  Never invent one.
- Named locks: GET_LOCK with a 10 s wait. Release in `finally` on every path (the PDO is not persistent:
  `config/database.php:131`).
- Race tests follow `scripts/tests/block_booking_race.php` / `scripts/tests/stock_count_race.php`: two real PHP processes,
  committing connections, THROWAWAY rows tagged and deleted by id, leftovers of an aborted run removed first. Single-process
  checks run in `scripts/tests/page_harness.php` (rolled back).
- Lint every changed PHP file (`php -l`). Run `node --check` on changed JS.
